# ECONOVA Architecture & Open Decisions Log

This document records the technical architecture chosen for ECONOVA and the safe, reversible defaults selected for open decisions in `DOIT_v2.md` §22.

## 1. Selected Technology Stack
- **Frontend:** React 19 + TypeScript + Vite + Tailwind CSS v4 + `vite-plugin-pwa` (Workbox).
- **Backend API:** Node.js + Express (`server.ts`) running on port 3000 (mounting `vite.middlewares` in dev and serving static `dist/` in production).
- **Database:** Hosted **Supabase PostgreSQL** via `pg` connection pool (`SUPABASE_DB_URL` or `DATABASE_URL`), managed by SQL migrations in `supabase/migrations/0001_initial_schema.sql` and Row-Level Security policies in `supabase/migrations/0002_rls_policies.sql`. Replaces the prototype local-filesystem SQLite storage (`./data/econova.db`) so learner progress, XP, assessments, and certificates persist reliably across Cloud Run deployments and autoscaling instances.
- **Authentication:** Scrypt salted password hashes (`crypto.scryptSync`) + HMAC-SHA256 signed `HttpOnly`, `SameSite=Lax` session cookies keyed by `SESSION_SECRET` (mandatory in production; no local filesystem secret persistence). Built-in sandbox quick-login buttons and demo accounts stay disabled unless `ENABLE_DEMO_SANDBOX="true"`.
- **Optional AI Drafting:** Server-side `@google/genai` proxy (`/api/ai/chat` and `/api/ai/generate-image`) gated on `GEMINI_API_KEY` from AI Studio Secrets / server environment only. Remains disabled in both API and UI until `GEMINI_API_KEY` is configured. All AI-generated learning content enters the editorial workflow strictly as `draft` and cannot auto-publish.

## 2. Resolved Defaults for `DOIT_v2.md` §22 Open Decisions
1. **Language & Script Convention:** Uzbek Latin (`uz`) and English (`en`) are modeled as independent `course_editions` with separate titles, descriptions, lessons, transcripts, assessments, and reviewer sign-offs. Neither edition falls back silently to machine translation of the other.
2. **Levels vs. Progressing:** Course difficulty is strictly `Beginner`, `Intermediate`, or `Advanced`. `Progressing` is modeled exclusively on `enrollments.journey_status` (`not_started`, `progressing`, `completed`, `paused`) and never appears as a fourth difficulty filter.
3. **Completion & Assessment Rules:** MVP uses single-answer multiple-choice assessments with server-side answer keys (`correct_option_index` never leaves the server before submission), configurable `passing_score_percent` (default `70%`), and explicit retry rules (`max_attempts_per_day`: 5). Course completion requires completing all required lessons and passing the course assessment.
4. **Non-Cash XP Policy:** Retained strictly as non-cash **XP** (`xp_ledger` append-only ledger). Awards are server-verified and idempotent (`+25` per required lesson, `+50` on passing assessment, `+100` on course completion, `+40` on verified referral claim, capped at `300 XP/day`). Zero cash withdrawal, conversion rate, or payout UI exists.
5. **Privacy & Safeguarding Defaults:** Leaderboard participation (`leaderboard_opt_in = false`) and certificate sharing (`share_enabled = false`) default to **private / opt-in**. Public leaderboards display only chosen pseudonyms inside bounded course/weekly cohorts. Certificate verification (`/verify/:token`) uses unguessable random tokens and exposes only minimal approved fields (`status`, `recipient_display_name`, `course_title`, `subject`, `level`, `locale`, `issued_at`, `non_accreditation_notice`).
6. **Learning Streaks:** Calculated per learner's configured IANA timezone (default `Asia/Tashkent`) only on meaningful server-verified events (lesson completion or assessment submission). Missed days never delete course progress.
7. **PWA Offline Scope:** Service worker caches only the application shell, static assets, and public catalog endpoints (`NetworkFirst`). Private `/api/me/*`, `/api/admin/*`, `/api/auth/*`, and `/api/ai/*` routes are strictly `NetworkOnly` so shared devices never leak learner records.
8. **AI Usage Policy:** Paid AI services are never required to launch or run ECONOVA. When `GEMINI_API_KEY` is configured in the host environment, editors can create `draft` lesson outlines (`gemini-4-hydrogen`, `gemini-4-argon`, `gemini-4-carbon`, `gemini-3.1-flash-lite`) and draft visual diagrams (`gemini-3-pro-image-preview`), all gated behind mandatory Subject, Language, and Rights/Accessibility human review before publication.
